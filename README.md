# Spray

A React web-based app allowing users to build and save climbing routes for their own custom climbing walls.

Spray works in a very simple way:

1) Upload an image of your climbing wall. Crop and adjust perspective if needed.
2) Create routes by clicking/pressing on holds in your image to generate markers.
3) Save the route, along with route name, setter name, V-grade difficulty, foot rule, and any special notes.
4) View the route again at any time!
5) Record ascents if you'd like, logging just your name and ascent date.

That's it! No user profiles, just a simple app to maintain a library of routes for your climbing wall.

It might be hard to use for walls with very dense hold layouts since the markers may cover multiple holds, but hey, it gets the job done for me, and maybe it will for you too! Below is a screenshot from an iPhone 17 Pro showing one of the saved routes:

## Getting Started

If you don't already have **Node.js** and **npm** installed, you will need them. Do not use `apt` to install these, though, since `apt` typically installs much older versions. There are a few options out there, but I used [Node Version Manager (NVM)](https://github.com/nvm-sh/nvm?tab=readme-ov-file). Once NVM in installed, you can install the latest Node.js and npm versions with:

```bash
nvm install node
```

Now clone this repository onto your own machine:

```bash
git clone https://github.com/zvanderbosch/spray.git
```

Move into the **spray** directory and then install all of the necessary packages with **npm**:

```bash
cd spray
npm install
```

Create a **db.json** file in the **spray** directory with the following contents:

```json
{
    "walls": [],
    "routes": []
}
```

This file will serve as the database storing your library of climbing walls and associated routes.

## Serving the App

With the above steps complete, simply run the following from your **spray** directory:

```bash
npm run dev:all
```

Now, any device that is connected to the same network as the device that's running the app will be able to access the app on a browser at the **Network** address printed out on the terminal, such as:

```
  VITE v7.3.1  ready in 121 ms

  ➜  Local:   http://localhost:3000/
  ➜  Network: http://YOUR_COMPUTER_IP:3000/
  ➜  press h + enter to show help
```

To shut down the app and database server, just type `ctrl+c` in the terminal running the app.

## Making the App Publicly Available

If you want to allow people to access your app publicly from any device or internet connection, you can use tools like [ngrok](https://ngrok.com/). All ngrok accounts get one free public domain, although these free domain names are randomly generated by ngrok and cannot be customized without paying a monthly or annual fee. I set this up for my instance of the app, though, using the free domain name and it seems to be working great.

If you do connect your app with a public domain, you'll need to add this domain to the list of allowed domains specified in your `vite.config.js` file. This config file loads the domain names from a local .env file. An example .env file (`.env.example`) is provided in this repository. Rename it to `.env` and add your domain(s), which will then be loaded into the config file.

## Importing Routes From an Old Wall to a New Wall

If at some point you add new holds to your wall, or move some holds around, you may want to update the wall's picture so these holds are included in the app. However, it will likely be very difficult to take a new picture that matches the perspective of the original image, causing hold markers from the old wall's routes to appear misplaced on the new wall. 

To aid in transferring routes from an old to new wall image, Spray has a built-in feature that allows users to create a new wall and use an image alignment tool to define an accurate transformation of hold marker positions from old to new images.

Here are the steps to follow to use the hold alignment and route import feature:

1) Create a new wall with your updated image
2) On this wall's home screen, select "Import Routes From Another Wall"
3) Select at least **4** holds, ideally more, that are common between the old and new images to establish the transformation that maps hold positions on the old image to hold positions on the new image.
4) Click "Continue" once you're happy with the alignment, then choose which routes to copy over from the old wall to the new wall.
5) Click "Copy" to complete the process. If copying a lot a routes over, this way take a few seconds.
